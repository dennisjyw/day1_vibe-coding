# 校務研究安全決策表

## 使用說明

這份表不是法律意見，也不是 IRB 申請書。它的用途是把資料分析或 Vibe Coding 任務先分流，避免在還沒有確認資料與研究條件前就把檔案上傳給 AI、放進前端或交給安全掃描工具。

## 1. 資料快速分流

- [ ] 全部資料都是合成資料，且沒有從真實資料衍生的可識別欄位。
- [ ] 資料不含姓名、學號、身分證號、聯絡方式、帳號、影像、自由文字或其他可識別欄位。
- [ ] 資料不含健康、醫療、心理、家庭、性別／性向、犯罪或其他高風險資訊。
- [ ] 即使與其他資料表、公開資料或時間地點組合，也不容易重新識別個人或小群體。
- [ ] 沒有 mapping table、原始名單或真實憑證放在專案目錄。

如果任何一項無法確認，不要把資料送入未核准的外部 AI 或安全掃描工具，先找資料管理者與校內窗口。

## 2. 用途與權責

- [ ] 已確認資料提供者與資料管理者。
- [ ] 已寫下研究／分析目的，而不是只寫「探索看看」。
- [ ] 已確認用途是否在原始告知、授權、校務職掌、研究計畫或委託契約範圍內。
- [ ] 已確認資料最小化欄位與必要保存期限。
- [ ] 已確認是否有委外、外部 AI、跨境傳輸、模型訓練、日誌保存或自動刪除問題。

## 3. 研究倫理／IRB 分流

回答以下問題：

- [ ] 研究對象是否是人？
- [ ] 是否有介入或互動？
- [ ] 是否進行以個人或群體為對象的系統性調查或知識性探索？
- [ ] 是否使用可識別特定當事人的資料？
- [ ] 是否取得、分析或運用人體檢體，或與個人生物行為、生理、心理、遺傳、醫學有關的資訊？
- [ ] 是否使用未去連結的研究材料，或可能將研究材料提供給其他機構／國外？

若任何一項為「是」或「不確定」：

1. 先停止自行宣告免審。
2. 整理研究目的、對象、方法、資料欄位、可識別性、資料來源、保存與分享方式。
3. 諮詢研究發展處、研究倫理窗口或 IRB，確認免審、簡易程序或一般程序。
4. 若是國科會、教育部或其他補助計畫，另核對計畫申請與執行要求。

## 4. 工具與專案邊界

- [ ] 本次操作只在已授權的專案目錄內。
- [ ] 前端只使用合成或已核准公開資料。
- [ ] API key、密碼、token、cookie、mapping table 不進 Git、不進前端、不進 Prompt。
- [ ] 不掃描整個 Home、Desktop 或含正式資料的目錄。
- [ ] 未確認外部服務資料處理條款前，不上傳真實校務資料。
- [ ] 若使用 Codex Security，只把它當作程式風險檢查，不把 finding 結果當作法律／倫理核准。

## 5. 輸出與再識別檢查

- [ ] 報表、圖表、錯誤訊息與下載檔沒有姓名、學號或可識別自由文字。
- [ ] 小樣本、稀有組合與交叉欄位不會暴露個人或小群體。
- [ ] 沒有把相關性寫成因果性，也沒有把 AI 生成的統計或引用直接當成事實。
- [ ] 已保留資料字典、清理規則、程式版本、Prompt、來源與人工驗收紀錄。
- [ ] 已記錄未解決風險、負責人與下一步。

## 6. 事件處理

若發現真實個資、憑證或正式設定誤進專案、Prompt、外部服務或公開輸出：

1. 立即停止不必要的傳輸與分享。
2. 不要把憑證或真實資料複製到聊天中求助。
3. 依學校個資／資安窗口與系統管理者流程處理撤銷、輪替、隔離、刪除與通報。
4. 保留必要證據與時間線，不自行覆寫或刪除可能需要調查的紀錄。
5. 完成修復後重新檢查專案、Git history、日誌、輸出檔與外部服務紀錄。

## 課堂預設答案

Day 1 課堂的預設答案是：

- 資料：合成 CSV。
- 憑證：只用假 key。
- 工具：不使用真實校務資料，不連接未核准外部服務。
- 安全掃描：只掃描授權的 `security-demo/` 或課程專案。
- 研究倫理：不把課堂合成資料示範冒充正式研究計畫的 IRB 判定。
- 交付：先交付可重現的分析報告與安全檢查紀錄，再談正式資料流程。
