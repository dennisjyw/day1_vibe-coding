# AGENTS.md

## Project Goal

本專案用於練習以合成校務資料分析註冊率、報到率與相關分組差異，並產生可追溯的分析摘要。

## Scope and Non-goals

### In scope

- 分析合成校務資料。
- 檢查資料品質與欄位定義。
- 計算並比較註冊率、報到率與相關分組差異。
- 整理可驗證的現象、假設、反證與下一步資料需求。

### Out of scope

- 不對真實招生政策提出結論。
- 不處理真實學生或教師資料。
- 不建立正式資料系統。
- 不執行未授權的外部資料查詢、上傳或掃描。

## Target User

校務研究分析人員，需在校務會議前整理可追溯的分析摘要。

## Project Map

- `data/ir_registration_synthetic.csv`：合成資料來源，不可修改。
- `data/data_dictionary.md`：資料欄位與定義說明。
- `prompts/02_data_exploration.md`：資料探索任務。
- `prompts/03_analysis_report.md`：分析報告任務。
- `prompts/04_iteration_check.md`：迭代檢查任務。
- `analysis.md`：分析報告輸出。
- `security-check.md`：安全檢查紀錄。
- `references/official-law-and-research-ethics.md`：法規、研究倫理與校內制度查證附錄。
- `COURSE_OUTLINE.md`：依 PDF 章節順序撰寫的講稿。

## Technical Environment

- 主要操作工具：Codex Desktop。
- 主要輸入格式：CSV 與 Markdown。
- 只在已授權的課程專案目錄中工作。
- 不假設未經確認的套件、命令或外部服務一定存在。

## Data and Evidence Rules

- 開始分析前，先檢查資料欄位、資料型別、筆數與缺失值。
- 任何指標都要說明分子、分母與計算方式。
- 先描述資料，再提出解釋與假設。
- 明確區分觀察、解釋、假設、結論與建議。
- 相關性不得直接寫成因果性。
- 不確定時列出需要補充的資料與可能反證。
- 若使用外部事實，優先使用官方、第一手或同儕審查來源，並記錄 URL 與查證日期。
- 不得捏造資料、來源、引用或分析結果。

## Working Rules

- 先理解目前任務的目標、範圍、限制與驗收標準。
- 如果歧義不會改變資料範圍、風險或完成定義，說明合理假設後繼續。
- 只有關鍵決策需要確認時才提問。
- 只修改完成目前任務所必要的檔案。
- 不進行無關重構、格式大改或工具鏈替換。
- 不修改原始 CSV；分析結果另存新檔。
- 對趨勢、流程或分組差異，若圖表或簡單 diagram 能降低理解成本，優先使用；圖表必須標示單位、樣本數與分母。
- 簡單且連續的任務不使用 subagent；若委派獨立工作，主要 Agent 必須重新驗證結果。

## Security Rules

- 不讀取或建立真實個資、mapping table、API key、密碼或 token。
- 不把課堂資料傳送到未授權的外部服務。
- 不掃描或存取專案資料夾以外的敏感檔案。
- 不將合成資料描述為真實校務結論。
- 不提交 `.env`、`.env.*` 或其他本機秘密設定；`.env.example` 只能放 placeholder。
- 不把任何會被前端打包或送到瀏覽器的環境變數當成秘密。
- `AGENTS.md` 是工作指引，不是安全控制機制；實際安全仍依賴權限、sandbox、核准流程、網路政策與檔案權限。

## Task-specific Rules for This Exercise

以下規則是學員在第一版 `analysis.md` 完成後加入的任務特定範例。講師可依人工驗收結果保留、修改或刪除，不要把示範門檻誤當成通用統計規範。

- 所有分組比率除百分比外，同時顯示分母。
- 課堂示範中，分母小於 40 的分組標示「小分母，僅供描述」；這只是本練習的警示門檻，不代表統計顯著性。
- 決策摘要固定分成「目前能說」「目前不能說」「下一步需要什麼資料」。
- 若資料不符合目前資料字典所定義的 342 列、11 欄，或必要欄位缺失，停止分析並回報，不自行猜測修補。
- 單次迭代最多修正一個經人工確認的主要問題；達標、達到本輪上限、缺少資料或需要人工決策時停止。

## Verification

- 使用實際工具讀取資料並重新計算關鍵指標，不只根據檔名或既有文字推斷。
- 至少驗證資料筆數、欄位數、資料型別、缺失值與主要指標的分子和分母。
- 重新讀取輸出檔案，確認內容與實際分析結果一致。
- 若新增或修改程式，執行相關測試、lint 或可重跑的分析命令。
- 若沒有自動化測試，明確說明限制，並執行可重現的人工檢查。
- 回報實際執行的工具或命令、檢查結果與尚未驗證的項目。

## Reporting

- 回報順序為：結論、關鍵證據、限制、下一步。
- 保持簡潔直接，不連續回報無意義進度。
- 清楚區分已完成、已驗證、推測與尚未完成。
- 不宣稱測試通過，除非實際執行過相關檢查。

## Acceptance Criteria

- 報告能回溯到資料欄位與計算方式。
- 指標的分母定義一致。
- 觀察、解釋、假設與結論彼此分開。
- 每個重要假設都有可能反證或後續查證方式。
- 報告列出資料限制與未驗證項目。
- 輸出不含真實個資、秘密或未授權資料。
- 交付前已實際執行必要的資料檢查與驗證。
