# 練習 4：迭代檢查

## 目的與產出

- 目的：比較第一版 `analysis.md` 與加入穩定規則後的第二輪結果，觀察 Prompt、Context 與 Harness 分別解決什麼問題。
- 輸出：先產生有證據的檢查結果，經人工確認後，只修正 `analysis.md` 的一個主要問題，並記錄修改前後差異與停止理由。

## 執行前提

執行本練習前，應已完成：

1. 由 `prompts/01_problem_brief.md` 至 `prompts/03_analysis_report.md` 產生第一版 `analysis.md`。
2. 人工驗收第一版，找出反覆出現的分子、分母、因果限制、證據規則或檢查步驟。

## 可直接貼入 Codex 的 Prompt

```text
Context
請依目前專案資料夾 AGENTS.md、原始 CSV、problem-brief.md、prompts/03_analysis_report.md 的驗收標準，檢查第一版 analysis.md。

Task
第一步先不要修改檔案。請列出：
1. 你實際讀取的規則、檔案與驗收標準。
2. 第一版已符合的驗收項目與證據。
3. 缺少資料證據或無法重現的數字。
4. 可能把相關性寫成因果性的句子。
5. 指標定義、分子或分母不清楚之處。
6. 新增的任務特定規則是否已被遵守，例如分組比率顯示分母、小分母提示、決策摘要結構與資料完整性停止條件。
7. 最值得先修正的一個主要問題、理由與受影響段落。

等我確認後，只修改這一個主要問題，重新計算受影響的數字，
並輸出修改前後差異、驗證證據、未解決問題與停止理由。

Constraints
- 不一次重寫整份報告。
- 不新增與本輪問題無關的功能或段落。
- 不修改原始 CSV。
- 不以文字看起來合理取代重新計算。
- 若沒有實際執行驗證，不得宣稱驗證通過。
- 最多完成一輪主要修正；若需要更多資料、風險超出課堂範圍或必須由人決策，立即停止並說明。

Acceptance Criteria
- 修改前先完成有證據的 Check。
- 清楚列出本輪實際使用的規則與 Context。
- Act 階段只處理一個經人工確認的主要問題。
- 修改前後差異清楚。
- 修改後重新計算，且仍保留資料限制與不確定性。
- 說明停止原因：已達標、達到本輪上限、缺少資料或需要人工決策。
```

## 人工驗收

- 有先列出實際讀取的規則與檔案
- 有先檢查再修改
- 有引用實際檔案、欄位或計算證據
- 一次只修改一個主要問題
- 修改前後差異清楚
- 修改後仍保留資料限制與不確定性
- 有說明停止理由與尚未解決的問題
